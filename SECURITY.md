# Security policy

Report suspected vulnerabilities privately. Do not disclose security details in
public issues, pull requests, discussions, commit messages, or screenshots.

## Reporting a vulnerability

1. Open the affected repository on GitHub.
2. Use **Security → Report a vulnerability** when private vulnerability
   reporting is available.
3. If that option is unavailable, contact a repository administrator or a
   Devmentech organization owner through the private communication channel
   already established with the team.

Include enough information to reproduce and assess the report:

- affected repository, version, commit, or deployment;
- vulnerability type and potential impact;
- reproduction steps or a minimal proof of concept;
- required permissions or environment assumptions;
- suggested mitigation, if known.

Do not include real credentials, customer data, or unnecessary personal data in
the report.

## Coordination

Maintainers will validate the report, determine the affected versions, and
coordinate remediation and disclosure with the reporter. Publish details only
after the maintainers confirm that a fix or mitigation is available.

Archived or explicitly unsupported repositories may not receive security
updates. Check the affected repository's status and documentation before
reporting.
